## 1. Toolchain (fixed in this branch)

**Roslyn pin above minimum breaks consumers on older SDKs — H [fixed].**
`Disruptor.Surface.Generator.csproj` pinned `Microsoft.CodeAnalysis.CSharp 5.3.0`, which
refuses to load on any SDK older than 10.0.3xx (e.g. Ubuntu's 10.0.1xx line). Failure
mode is nasty: one easy-to-miss CS9057 warning, then ~185 misleading CS9248 errors
("partial property must have an implementation part") because the generator silently
contributed nothing. No 5.3 API is used — lowered to 5.0.0; build + 300/300 tests pass.

## 2. Generator — emission bugs

### 2.1 Same-named relation kinds in different namespaces silently share one edge table — H [reproduced in the shipped sample]
`SchemaEmitter.cs:481,502` derives the SurrealDB edge-table name from the attribute's
*simple* class name. The sample has two `ReferencesAttribute` kinds
(`Relations/ReferencesAttribute.cs` and `Spike/CodeRelations.cs`) → the committed
generated schema (`Workspace.Schema.g.cs:220` and `:228`) contains **two**
`DEFINE TABLE IF NOT EXISTS references` chunks. The first (observations → design union)
wins; the Spike kind's `FROM code_symbols TO code_symbols ENFORCED` is a no-op, its
`DEFINE FIELD confidence` lands on the wrong edge table, and every
`INSERT RELATION INTO references` from a `CodeSymbol` is rejected at runtime by the
`ENFORCED FROM` clause. No diagnostic fires.

### 2.2 Duplicate simple names crash the whole generator or silently merge tables — H [reproduced]
- `AggregateLoaderEmitter.cs:34,61,133` keys the loader class + `AddSource` hint on the
  root's simple name in a fixed namespace. Two `[AggregateRoot] Design` classes in
  different namespaces → duplicate hint → `ArgumentException` → CS8785, generator
  contributes nothing, dozens of misleading CS9248/CS0246 errors, zero CG diagnostics.
  `CompositionRootEmitter.cs:51` and `LoadEntryEmitter.cs:57,65,106` share the pattern.
- `QueryRootEmitter.cs:70` / `HydrateRootEmitter.cs:66` use `Pluralize(table.Name)`:
  `[Table] Item` + `[Table] Items`, or `A.Design` + `B.Design`, → CS0102/CS0111 in the
  generated roots — and for same-simple-name tables `SchemaEmitter.cs:180` maps both CLR
  types to one physical table, interleaving both field sets: **two distinct CLR types
  silently share rows**. (`RelationVariantEmitter.cs:236` even comments that "existing
  CG-checks would have rejected that earlier" — no such check exists.)

**Fix shape for 2.1 + 2.2:** one pre-emit uniqueness registry (physical table names, edge
names, pluralised accessor names, `AddSource` hint names) reporting a CG error naming
both colliders.

### 2.3 Duplicated pipeline models from multi-file partial types crash the generator — H
The three `CreateSyntaxProvider`-based extractors (`RelationVariantExtractor.cs:37`,
`RelationKindExtractor.cs:23`, `SharedShapeExtractor.cs:52`) run once per *declaration*,
but `GetDeclaredSymbol` merges partials — a relation variant split across two files where
the second declaration carries any attribute produces two identical models, and
`RelationVariantEmitter.cs:370` calls `AddSource` twice with the same hint →
`ArgumentException` → CS8785, everything disappears. Nothing in `RelationLinker.Build`
dedupes (union-endpoint candidates are the one deduped set, `RelationLinker.cs:664`).
Models are value-equal, so a `Distinct()` per collected set at the top of `Build` fixes it.

### 2.4 Nested `[Table]` classes emit broken code with no diagnostic — H
`TableExtractor.cs:43` builds `FullName` as `{namespace}.{MetadataName}`, dropping
containing types — inconsistently with `NormaliseFullName` (`:329`) used everywhere else.
A nested `[Table]` emits its partial at *namespace* scope (orphan type → CS9248/CS9249
storm), two nested tables with the same simple name collide on hint names, and every
string-keyed graph lookup (aggregate membership, cascade cycles, CG017/CG021) silently
misses. Either reject nested tables with a CG error or key everything on the normalised
name. Same pattern in `CompositionRootExtractor.cs:28`.

### 2.5 Generic `[Table]` FullName never matches use sites — M
`MetadataName` yields `` Ns.Foo`1 `` while use-site names strip to `Ns.Foo`
(`RelationLinker.cs:994` `Strip`). Generics are half-supported (`TableModel.TypeParameters`
exists, `PartialEmitter.cs:80` emits `partial class Foo<T>`), but aggregate membership,
CG014 cycle detection, and CG017/CG021 all silently skip generic tables.

### 2.6 Primitive-element collections emit non-compiling C# — H [reproduced]
`TableExtractor.ResolveInlineMembers` (`:137-161`) walks *all* public instance properties
of the element type. `[Property] IReadOnlyList<string> Tags` generates
`new string(this[]: …, Length: …)` → CS0443/CS1739; `List<int>` falls to the scalar path
→ no matching `ContentValue.Set` overload → CS1503. CG025 explicitly skips collection
shapes (`ModelGenerator.cs:517`), so the user gets raw syntax errors inside a `.g.cs`.
Either support primitive-element collections end-to-end (the hydration read side already
exists) or reject with a diagnostic; and filter `ResolveInlineMembers` to
settable, non-indexer, schema-mappable members.

### 2.7 Turkish-locale builds bake corrupted identifiers into schema/DDL — M/H [reproduced]
`SurrealNaming.cs:22-34` — Humanizer 3.0.10's `Underscore()`/`Pluralize()` lower-case with
the **current culture**. Under `tr-TR`, `"Issue"` → table `ıssues` (dotless U+0131), and
the same applies to field names, edge names, slice keys, and index names — baked into the
model at analysis time (`RelationVariantExtractor.cs:185`, `RelationLinker.cs:233,320`).
Generated code still compiles, so a Turkish-locale machine silently produces a schema
incompatible with everyone else's. Wrap the Humanizer calls in invariant culture and add
a `tr-TR` emission test.

### 2.8 Property/class names that are C# keywords emit non-compiling partials — M [reproduced]
Roslyn strips the `@` from `p.Name` (`TableExtractor.cs:78`), and emitters interpolate the
bare name: `[Property] partial string @class` → `public partial string class { … }` →
CS1519 cascade. Escape via `SyntaxFacts.GetKeywordKind` at the emit boundary.

### 2.9 Other emission defects — M/L
- **Element collection declared with a setter** (`PartialEmitter.cs:249-265` ignores
  `HasSetter`): `partial IReadOnlyList<T> X { get; set; }` → CS9252, no diagnostic. — M
- **`Guid` schema/write mismatch**: `SchemaEmitter.cs:437` maps Guid to `TYPE string` but
  `ContentValue.cs:96` writes a CBOR `SurrealUuidValue` → every save of a Guid property
  on a SCHEMAFULL table is rejected. (`Ulid` was handled, `ContentValue.cs:107`; Guid was
  missed. Query binding `SurfaceQueryCompiler.cs:366` has the same mismatch.) — M
- **Variant duplicate-edge id drift**: payload-bearing variant save
  (`RelationVariantEmitter.cs:884`) mints a fresh id into `__content["id"]` and
  `MarkSaved`s it; on the `ON DUPLICATE KEY UPDATE` path the substrate keeps the existing
  row id, so the session records an id that doesn't exist in the DB. — M/L
- **Nullable typed-id endpoint NRE**: `RelationVariantEmitter.cs:700-706` emits
  `(RecordId?)(RecordId)_source` for a nullable typed-id endpoint — throws
  `InvalidOperationException` when null instead of yielding `(field, null)`; the union
  branch (`:688`) guards correctly. — L
- **`Quote` escapes `"` but not `\`** (`PartialEmitter.cs:1164`,
  `RelationVariantEmitter.cs:1028`); `SharedShapeEmitter.cs:125` has the correct
  two-step escape — consolidate. — L

## 3. Generator — analysis/pipeline bugs

- **Malformed variants dropped silently — M.** Two `[In]` properties, or a lift that
  resolves no endpoints, return `null` from `RelationVariantExtractor.cs:129` /
  `RelationLinker.cs:391` with comments promising a diagnostic "in a later phase" that
  can never see the dropped model. User gets a CS9248 wall, no CG error.
- **`[Table]` on `record` declarations silently ignored — M.** `AttributeTargets.Class`
  admits records; the FAWMN predicate (`ModelGenerator.cs:18`) only matches
  `ClassDeclarationSyntax`. No code, no diagnostic. Reject with a CG error (or support).
- **Incremental-cache busting — M.** `IndexAnnotationModel` embeds
  `DeclarationKey = "{filePath}:{spanStart}"` and `SourceOrder = SpanStart`
  (`TableExtractor.cs:274`): adding a comment above an index-annotated property changes
  equality → the single monolithic `RegisterSourceOutput` re-emits **every** file. This is
  the exact regression `docs/architecture.md`'s contract warns about. Use
  position-independent ordinals. Related: `RelationLinker.Build` ignores the cancellation
  token entirely.
- **Union marker resolved by simple-name with arbitrary fallback — M.**
  `RelationLinker.ResolveMarkerToTable` (`:708-742`) falls back to the *first* table of a
  matching simple name across namespaces (`anyMatch ??= t`) — which table joins the union
  can flip with file ordering, no diagnostic.
- **Diagnostics all report at `Location.None`** — errors land on the project node, not
  the offending declaration. Capture an equatable `LocationInfo` at extraction. — M (UX)
- **Minor holes — L:** multiple delete-behavior attributes on a variant endpoint take the
  first silently (entities get CG013, variants nothing); a property with two relation
  attributes models only the first; culture-default `StartsWith/EndsWith` on structural
  string checks (`ModelGenerator.cs:657,721`, `RelationLinker.cs:714,997`, etc.) should be
  `StringComparison.Ordinal`.

## 4. Runtime — session core bugs

- **`DateTime` handling is timezone-dependent and crashes east of UTC — H.**
  `ContentValue.cs:76` (and `:82`, mirrored in `SurfaceQueryCompiler.cs:368`) casts
  `DateTime` → `DateTimeOffset`, interpreting `Unspecified`/`Local` as machine-local.
  Saving an entity with an unassigned `[Property] DateTime` (`default`, Unspecified) on
  any UTC+N machine throws `ArgumentOutOfRangeException` mid-save (closing the session);
  wall-clock values silently shift instants on round-trip (hydration returns
  `UtcDateTime`, `HydrationValue.cs:252`). Treat Unspecified as UTC (or reject Local).
- **`PlanDelete` can't see `[Parent]`-link REJECT blockers — M.**
  `ReferenceRegistryEmitter.cs:50` registers only `PropertyKind.Reference`, but the schema
  makes every parent link `REFERENCE ON DELETE REJECT` (`SchemaEmitter.cs:314`). Deleting
  a design with loaded children finds zero blockers, dispatches, and surfaces a generic
  `SurrealRpcException` with a closed session instead of the documented pre-flight
  `CascadeRejectException` with `Blockers` (contradicts `SurrealSession.cs:969`).
- **Re-running a variant query returns detached duplicates — M.**
  `HydrateOneVariant` (`SurrealSession.cs:1407`) always returns the freshly-constructed
  instance even when the sink deduped it against an already-tracked one — the returned
  object has `Session == null`, the tracked one keeps stale payload, and saving the
  duplicate swaps the identity map to a second live instance (the exact poison public
  `Track` throws to prevent, `:428`).
- **`FetchAsync` is exempt from fail-closed — M.** `SurrealSession.cs:491-519` has no
  `catch { closed = true; }` and never calls `EnsureSuccess()` beyond statement 0 — a
  mid-loop hydration failure leaves an open session that is half old state, half new,
  violating the documented one-shot invariant (`:219`).
- **Low-severity cluster:** `CleanupLocalState` (`:1698`) never purges `loadedAtStart` /
  `LoadedSlices` (stale `IsTracked` → forward-dep walk skips re-saving a deleted ref;
  slow leak); tracked variant entities become ghosts when an endpoint is deleted;
  `Track` is non-atomic when a user `OnCreate*` hook throws (`:438`); `DeleteAsync` lacks
  the cross-session guard `SaveAsync` has (`:974` vs `:791`); `AdoptIfUnbound` silently
  no-ops for a child bound to a *different* session (`:688`); unchecked int narrowing in
  `HydrationValue.ConvertValue` (`:212`) silently truncates out-of-range DB values;
  `default(RecordId).IsIdempotent` NREs (`RecordId.cs:45`) and the library itself logs
  `default` edges (`CommandLog.cs:80`); `SurrealFormatter.Identifier`'s `$` anchor admits
  a trailing `\n` — use `\z` (`SurrealFormatter.cs:29`).

## 5. Query layer bugs

- **`Eq(null)` can never match data this library wrote — H.** Every nullable
  `ContentValue.Set` **omits** the key when null (stored value is `NONE`), but
  `SurfaceQueryCompiler.cs:350` compiles `Eq(null)` to `field = $p` with `$p = NULL` —
  and `NONE == NULL` is false in SurrealDB. `Where(XQ.Notes.Eq(null))` silently returns
  zero rows, always; `Not(Eq(null))` is wrong in the mirror direction; and there is no
  `IsNone()` predicate to express the correct thing. Compile null-Eq to
  `(field IS NONE OR field IS NULL)` and add `IsNone()/IsNotNone()`.
- **Projections can't be ordered by non-projected fields — M.** `CompileProjection`
  (`SurfaceQueryCompiler.cs:47-77`) doesn't widen the SELECT list for ORDER BY fields —
  the exact SurrealDB 3.x error (`Missing order idiom`) that `CompileIdsOnly` (`:92`) and
  the edge compiler already work around. Zero tests cover `CompileProjection`.
- **String functions error whole queries on `NONE` fields — M.**
  `string::contains(field, $p)` emitted bare (`:322-324`); one row with an unset
  `string?` field fails the entire SELECT under SurrealDB strict typing. Guard with
  `field != NONE AND …`.
- **Identifiers validated but never quoted — M.** A property named `Order`, `Group`,
  `Limit`, `None`, or `Value` renders bare into SurrealQL (`none` parses as the literal →
  silently always-false). Backtick-quote identifiers unconditionally at the
  `SurrealFormatter` chokepoint.
- **Low:** `ulong` predicate operands wrap negative (`:359`, use `checked`); `byte[]`
  binds as a list of int64s instead of `SurrealBytesValue` (`:374`); `TimeSpan`/enum are
  bindable in `Where` but unreadable at materialise time (`HydrationValue.cs:198-283`);
  `ExecuteIntoSessionAsync` (`SurfaceQuery.cs:290-316`) desyncs entity/row indexes if any
  response row is a non-object; the projection discovery probe records only the branch
  taken with default values — conditional `row.Read` calls silently drop columns
  (`IProjectionRow.cs:41`, deserves a doc warning or a two-probe determinism check);
  include-alias collisions (`BuildChildSubselect`) are never validated.

## 8. New feature/API suggestions (not in Improvements.md)

- `ExistsAsync()` (compile shape already exists for count) and
  `FirstOrDefaultAsync`/`SingleAsync` terminals.
- NONE-aware predicate vocabulary (`IsNone()`/`IsNotNone()`) — fixes §5's H-finding at
  the API level.
- Session close-reason diagnostics: `closed` is a bare bool set from six catch sites;
  capture the closing operation + exception and surface it in `ThrowIfClosed`.
- Reverse-reference index for `PlanDelete` — currently O(cascade × entities × refs);
  build the incoming-reference map once per plan.
- Per-element output granularity + `WithTrackingName` regression tests to mechanically
  enforce the equatability contract (would have caught §3's cache-busting bug).
- Equatable location capture so diagnostics point at the offending declaration.
