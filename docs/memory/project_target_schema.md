The generator's real-world target is a review/spec/design domain on SurrealDB with two aggregate roots: **Design** (Constraint, Epic, Feature, UserStory, AcceptanceCriteria, Test) and **Review** (Finding, Observation, Issue, DesignChange). Both share `Details` as a per-entity narrative payload. Cross-aggregate relations (`references`, `concerns`, `revises`, `assesses`) bridge the two roots.

Recurring structural patterns and how the generator covers them:

- **Optional `details` ref** — every domain table has an optional `details` reference declared as `[Reference, Inline] partial Details? Details { get; set; }`. The `[Inline]` marker tells the loader to emit the `details.*` projection so the linked record hydrates alongside its owner. Without `[Inline]`, plain `[Reference]` becomes a foreign pointer (id-only); the user must load it separately. Setter is a pure backing-field write; SaveAsync at dispatch time reads the field and emits the right CREATE/UPSERT for the inlined record before the owner. The mandatory-form `[Reference] partial Details Details { get; }` (get-only, non-nullable) emits an `OnCreate{Name}` partial-void hook that the user implements; `IEntity.Initialize` runs the hook during `Track` to mint the target.
- **Optional record fields** — e.g. `option<record<designs>>` for parent links. Modelled as `[Parent] partial T Name { get; set; }`. Setter is pure backing-field plus a `((IEntity)value).Session?.AdoptIfUnbound(this)` so a freshly constructed `new Constraint { Design = design }` joins design's session.
- **COMPUTED reverse children** — e.g. `constraints ON designs COMPUTED <~(constraints FIELD design)`. Maps to `[Children] partial IReadOnlyCollection<T> Name { get; }` on the parent side. Read-only — children are managed by setting the child's `[Parent]` property (which cascade-tracks via AdoptIfUnbound).
- **Scalar fields** — `description`, `repository_root`, `as_a`, etc. → `[Property] partial T Name { get; set; }`. Setter is a pure backing-field write (preview.40); no session interaction.
- **Element collections** — `scenarios`, `facts` etc. → `[Property] partial IReadOnlyList<TElement> Name { get; }` where `TElement` is a plain record (`Scenario(string Kind, string Description)`, `Fact(string Kind, string Arrange, string Act, string Assert)`). Generator emits a backing `List<TElement>` plus `Add{Singular}` / `Remove{Singular}` / `Clear{Plural}` helper methods. SaveAsync walks the list at dispatch time and writes the column as a typed `SurrealList<SurrealObject>`. (`SurrealArray<T>` was deleted preview.41 once the typed-CBOR pipeline made the wrapper redundant.)
- **Graph relations** via `DEFINE TABLE x TYPE RELATION FROM y TO z ENFORCED` — edge tables: restricts, validates, informs, cites, references, concerns, resolves, revises, assesses. Each pairs with a forward/inverse kind attribute (`RestrictsAttribute` + `RestrictedByAttribute`, etc.). Generator emits a sibling marker class without the `Attribute` suffix (`Restricts : IRelationKind`) per forward kind. On the source side: `partial IReadOnlyCollection<IEntity> Name { get; }` (within-aggregate) or `IReadOnlyCollection<IRecordId>` (cross-aggregate). Mutations go through async `Session.RelateAsync<TKind>(...)` against a `SurrealTransaction` — no auto-emitted Add/Remove/Clear, no sync `Session.Relate` (deleted preview.45). Each relation table also gets a `DEFINE INDEX … COLUMNS in, out UNIQUE` so duplicate edges are gated at the schema layer; `RelateAsync` dispatches `tx.UpsertAsync(edge.ToSdk(), { in, out, …payload })` with the deterministic Idempotent edge id, so re-runs land on the same row in place of tripping the unique index.
- **Union TO targets** — `TO designs|constraints|epics|...`. Generator emits a marker interface per multi-member union side (`I{InverseName}` for targets — `IRestrictedBy`, `IReferencedBy`, …; `I{Singularize(ForwardName)}` for sources). The interface inherits `IEntity`. Each entity in the union has the interface added to its base list automatically. Endpoint type safety on user-side passthroughs comes from declaring `(IRestrictedBy x)` as the parameter type. Cross-aggregate has parallel id-side unions (`I{InverseName}Id`) so `{Name}Id` structs share endpoint type witnesses.
- **REFERENCE ON DELETE** — `[Reject]` / `[Cascade]` / `[Unset]` / `[Ignore]` on a `[Reference]` field emit the matching `REFERENCE ON DELETE {policy}` clause on the field DDL. Substrate enforces at COMMIT (see `project_reference_state.md` for the in-library cascade gap that survives).

**Why:** Anchors the generator's design decisions — every Surreal pattern in the target schema has a corresponding C# shape, and the absence of one in this list means the generator currently doesn't cover it.

**How to apply:** When evaluating a proposed generator feature, check it against these patterns first. If a proposed shape doesn't correspond to anything here, ask whether it's actually needed.
