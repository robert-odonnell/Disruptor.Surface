When a conversation produces conclusions worth persisting across sessions — architectural framing, planned work sequences, strategic risks, scope decisions — just save them. Don't surface a menu of "what should I save and how?" choices.

**Why:** User said directly: "I'm not going to micromanage that." Asking them to choose what to save adds the same friction the memory system is supposed to remove. The whole point of auto-memory is that future-me arrives prepared without the user having to curate.

**How to apply:**
- After a conversation that yielded substantive conclusions, save the substance to memory before the session ends. Use the existing types (project / feedback / reference / user) as guides.
- Briefly tell the user *what* I saved (one line per memory) — not as a permission request, just so they know it's captured.
- If conclusions feel too soft or in-flight to commit, save them anyway with a "this is direction not decision" framing — a future session reading the memory can still tell the difference.
- The exception is genuinely sensitive content (anything the user flagged as "don't write this down") — those still warrant a check.
